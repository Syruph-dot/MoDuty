# 值日生参考会话与会话浓缩信息需求

> 状态：需求梳理中；先记录已明确目标和代码事实，待 grill-with-docs 逐项定稿后实施。
> 范围：值日生检索到参考会话后，新建执行者并派发任务的路径；历史会话原文仍按需检索。

## 目标场景

1. 人向值日生发送当前指令。
2. 值日生通过现有会话检索找到与当前任务有关的旧会话。
3. 如果决定新建执行者，系统为执行者建立其绑定会话；值日生从真实候选中选取参考会话。
4. 派发任务书保留当前指令，并带上所选参考会话的 ampersand 句柄。
5. 执行者收到任务时，除句柄外，还能看到与当前任务相关、长度受控、可追溯的会话浓缩信息；需要细节时再使用会话工具读取原始 turn。

本需求改写此前“只有句柄、完全按需自读”的边界：自动注入限于简短预览，全文不自动展开。新建执行者路径与复用既有执行者路径须分别验收。

## 初始需求条目

- R1：参考会话句柄必须指向真实存在的会话，来源于本次检索/检视结果；去重并保持可追溯选择原因。无合适候选时不编造链接。
- R2：新建执行者的任务书保留人的当前指令和验收要求，并显式携带被选中的参考会话句柄；台账记录与实际下发文本一致。
- R3：每个会话维护多条可独立选取的浓缩条目；条目不能覆盖或替换原始消息、turn 或既有 Compact Handoff。
- R4：浓缩条目应区分目标、已验证结果、当前状态、重要决策、未决事项；保留消息/turn/产物来源、生成版本与时间，不复制秘密或冗长工具输出。
- R5：派发时只选与当前任务相关的少量浓缩条目，受明确预算约束；执行者仍可按句柄 inspect、search、read 原始 turn。
- R6：注入信息是“参考材料”，人的当前请求仍是唯一权威任务文本；旧会话结论可能过时，执行者使用前按需核验。
- R7：新建执行者的直接派发分支与确认问题后“新建”的自动派发分支均需覆盖；复用分支是否采用同一机制待定。
- R8：测试覆盖无候选、重复/失效句柄、缺失或过时条目、超预算、错误来源、秘密过滤，以及任务书/台账/模型输入的一致性。

## 待定决策（每次只讨论一个）

1. 浓缩条目的生成与刷新时机：持续维护、派发时按需生成，或混合模式；缺失和失败如何降级。
2. 值日生选择参考会话的数量、相关性门槛与后端是否强制校验候选来源。
3. 浓缩条目的主题粒度、状态模型、人工编辑/否定机制及保留期限。
4. 执行者首轮与后续轮何时注入、同一条目是否重复注入、与自身 Compact Handoff 如何共同占用预算。
5. 检索到归档/已删除/权限受限会话时的展示与派发规则。

## 验收场景草案

- 人提出新任务，值日生检索并选中一个旧会话，新建执行者；最终任务书含一个真实 ampersand 句柄，执行者首轮看到对应的简短浓缩条目和来源，仍能按需读取原 turn。
- 同一个旧会话有多个主题条目时，仅注入当前任务命中的条目；其他条目不占上下文预算。
- 参考条目缺失或生成失败时，不编造摘要或完成状态；具体降级动作待决策 1 定稿。
- 用户选择“新建”而非“复用”后自动派发，产出的任务书、台账、执行者首轮信息与直接新建路径一致。
