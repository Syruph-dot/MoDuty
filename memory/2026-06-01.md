概述

**文档解构器。对于给定的文档，你要分割并生成一个或多个Chunk。忠于原文，不得缺漏，不得篡改。**

此 Skill 用于将一个或多个文档（Markdown、文本、或富文本导出）拆分为若干语义上独立且有意义的 Chunk，并将每个 Chunk 以 Lapix 可识别的 Chunk 格式保存。若文档无需拆分（短文或单一意图），Skill 可选择不拆分，直接将整篇作为单一 Chunk 保存。

触发条件

- 用户启动 Skill并在指令中指定了文档。

输入

- `documents`: 文档路径列表，或单个文档的字符串内容。
- 可选参数（见“参数”节）：拆分策略、最小/最大长度、是否生成摘要等。

参数

- `min_chars` (int, default: 300)：当使用语义或段落拆分时，最小字符长度阈值，低于则不再拆分。
- `max_chars` (int, default: -1)：单个 Chunk 的最大目标字符数，超过时可再次拆分或摘要化处理。
- `context_summarize` (boolean, default: true)：是否为每个 Chunk 生成上下文的摘要，用于提供上下文信息。

输出格式

每个 Chunk 建议保存为一个 Markdown 文件，文件内以 YAML frontmatter 描述 Chunk 元数据，正文为 Chunk 的内容。例如：

```yaml
---
id: chunk-{date}-{random_hash}
source: 某路径/某文件.md
chunk_index: 1
type: note
created_by: DocToChunk
created_at: 2026-04-12T10:00:00Z
links: ["[[xxx]]"]
tags: [meeting, decisions]
metadata:
	xxx: yyy
---

---
context-prior: "前一个Chunk的摘要或链接"
context-next: "后一个Chunk的摘要或链接"
---

（此处为 Chunk 正文内容）


```

此外，Skill 应当检查是否维护了Chunk和原文档的双向映射关系。无需全局索引，但应确保每个 Chunk 的 frontmatter 中包含足够的元数据（如 source 路径、chunk_index）以便后续追溯和关联。

```

工作流程（建议实现步骤）

1. 读取输入文档并解析 frontmatter（若存在），将原始元数据并入 Chunk.metadata.source_frontmatter。
2. 根据 `method` 选择拆分策略：
	 - `headings`: 以 Markdown 标题（H1/H2/H3）为边界拆分；适合结构化笔记。
	 - `paragraphs`: 以空行分段拆分。
	 - `sentences`: 将文本按句子切分并按 `max_chars` 合并成 Chunk。
	 - `semantic`: 文段并没有严格遵守md格式时，由Agent自行根据语义决定。
3. 对每个候选 Chunk 应用长度阈值（`min_chars`/`max_chars`，max_chars 默认为 -1，代表无上限），必要时合并或进一步拆分。
4. 可选：调用摘要器生成 `summary` 字段；提取 TOC/链接并填充 `links`。
5. 为 Chunk 生成稳定 ID（`id_strategy`），计算 `signature`（如 sha256(source_path + offset + content)）。
6. 写入 Chunk Markdown 文件并更新全局索引。
7. 返回每个文档的 Chunk 列表与索引位置供后续 Skill/Operator 使用。

去重与合并策略

- 若新生成的 Chunk 与已有 Chunk `signature` 相同，Skill 应跳过写入以避免重复。
- 提供 `force` 参数以强制覆盖旧 Chunk（谨慎使用）。

文件命名与存放约定

- 存放目录：`{output_folder}/{year}/{month}/`
- 文件名：`{id}.md`。

示例：

- 输入：`某路径/某文件.md` 内容含“推延备忘”段落。
- 输出：`.\L2-Chunks\{year}\{month}\` 下生成 `chunk-20260412-0001.md`，frontmatter 如上，并在 `chunks/index.json` 中记录映射。

实现建议与注意事项

- 保留源文档的 frontmatter 到 Chunk.metadata.source_frontmatter，便于保留上下文（如 author/date/tags）。
- 对长文档优先使用 `headings` 或 `semantic` 方法以获得更语义化的拆分；对短文或日志条目可直接不拆分。
- 在使用语义方法时，提前计算 embedding 并缓存以加速重复处理。
- 对于多语言文档，先做语言检测以选择合适的句子分割器与摘要策略。
- 将 Chunk 写入操作设计为幂等（若 signature 未变化则跳过写入），便于重复运行 Skill。

测试用例

- 小样例文档（2-3 段）应产生 1 个或 2 个 Chunk，且 `index.json` 能映射回源文件。
- 对同一文档重复运行 Skill（无修改）时，不应新增新的 Chunk 文件。

兼容性

- 输出 frontmatter 字段与 `Lapix` 计划中的 Chunk frontmatter 规范保持一致（参见 `Chunk frontmatter` 设计文档）。
- 为便于 Obsidian/obsidian-skills 兼容，Chunk 文件应为标准 Markdown，frontmatter 使用 YAML。
